日期：2026-10-16。样本：`D:/PrismSUN/libprism-sun.so`，SHA-256 `92e7d4adda7e222aa9dce389009a186adabb2602b80d618d417e0f6d509adaf4`。

结论：除已交付的 C++ 子集外，至少还有事件 32 的 `.mcp` 文件/脚本痕迹采集、事件 20 的进程映射信息采集，以及宿主门控和既有检测链的未还原部分。两条事件采集链并不等于两条已经证实会判作弊或封禁的规则。它们在旧报告中已有入口，本次补充了含义和调用证据，不是宣称新发现此前完全未知的检测模块。

本次逆向仅使用 IDA Pro MCP，没有使用 REA 或子代理。没有执行样本、修改原始 SO、重新构建已有 C++ 或重复已有测试。地址均为 imagebase=0 数据库中的地址。数据库全局自动分析未完成，本盘点不作全覆盖承诺。

事件 20 细节：已有验证字符串包括 `/data/app/`、`/data/data/`、`/data/user/`、`/packcache/`、`/lib`、`/dev/zero (deleted)`、`[anon:`。这些表明映射与加载路径处理的范围，但不足以逐项判定它们是白名单、黑名单或最终上报字段。`0x3b3860` 反编译存在 bad-SP 警告，应以汇编继续还原。未验证字符串候选不用于结论。这条采集链与环境内存专项中的四库 CRC 比较不同。

## 2. 已研究但只完成部分 C++ 的点

- seccomp / SIGSYS：已有状态聚合模型；`Seccomp:`、`Seccomp_filters:`、`NoNewPrivs:` 的采集、处理器所属映射和 `0x471c8c` 原因码生产者尚未全部还原。不能把 `NoNewPrivs` 单独算成已确认独立检测。
- 类可见性事件 22：已有配置驱动的 FindClass 模型，但实际类名单和配置来源未闭合，不能直接称为完整 Xposed 检测。
- 入口指令自检：已有 B / BRK / BR 模式分类器，但各函数的完整触发逻辑尚非全部等价还原。
- 环境映射过滤：`0x5f917c`、`0x5fb6b0` 尚未完全化简，属于已有环境内存链的剩余工作，不按函数数量重复计为独立检测项。

## 3. 时间项的证据边界

本次重新查询导入跳板 `0x78a540` 的直接交叉引用，得到五个调用点：四个位于 `0x140c9c`，一个位于 `0x744750`。`0x744750` 唯一已识别直接调用者是 `0x140c9c`；`0x140c9c` 唯一已识别外部直接调用者是 `0xf5198`（另有自身数据引用）。

既有分析已确认 `0x140c9c` 尝试 clock ID `[4,1,2,3]`，失败回退到 `0x744750` 的 CLOCK_MONOTONIC。`0xf5198` 将时间、PID 等组成缓冲区后经虚调用消费，与熵输入用途相符。当前没有证实时间差阈值、跨时钟差值比较或作弊裁决。因此应称为“已定位、未完整还原的时间获取链”，不能仅凭多种时钟就确定为变速检测或时间反调试。

这不排除其他间接调用、直接系统调用或宿主侧存在时间检测；如果所指为另一条时间检测，需要定位其具体判定入口。
