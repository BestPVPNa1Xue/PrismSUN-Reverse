# Prism 剩余检查点与证据覆盖审计

日期：2026-10-18（Asia/Shanghai）。范围：工作目录交接、专项进度、保存证据与一次 IDA Pro MCP 静态复核。按本轮要求单线程推进，没有调用 REA、没有启动子代理、没有执行原 SO 或 Android 客户端，也没有重跑既有测试。

## 结论

**还有明确未闭合的检查逻辑，不能宣布 Prism 的检查点已经挖完。** 最值得继续的是事件 20 的进程 maps 采集、seccomp/SIGSYS 原因码、事件 22 的配置来源/实际类名单，以及宿主启动门控。四库映射过滤与函数入口自检的覆盖核算也未完成。

但“存在未还原分支”与“已发现一套此前未知的检测模块”不同。本次注册侧复核补出旧盘点未单列的任务 ID 36；其已恢复正常执行路径返回 None，没有据此新增一项反作弊检测。当前证据也不足以新增 Root、模拟器、Frida、KeyMapper 专用规则或变速检测结论。

不提供完成百分比：尚无覆盖所有直接/间接调用、动态配置和本地终止路径的可靠分母。已有测试通过数表示各自限定范围内的验证，不表示全库覆盖率。

## 2. 本轮新增：从任务侧交叉核对事件清单

**任务 ID 与事件 ID 必须分开。** 例如任务 33 输出 event20，event33 则由任务 38 生成；任务 36 没有因为其 ID 就必然存在 event36。

任务 36 的新增证据：

1. `0x725fe4 → 0x744744 → 0x725c04`，后者在 `0x725d9c` 向注册包装传 `0x24`；`0x744460 → 0x726420` 进一步调用共同注册包装。
2. `0x794050` 的 `+0x18` 指向 `0x73c5c8`，已恢复返回值为 36；`+0x40` 指向 `0x73ce64`。
3. `0x73ce64` 的正常路径在 `0x73d074` 调用 `0x6d49a8`；后者在 `0x6d4c74` 将结果 kind 写为 1。相同 helper 已用于无障碍/输入法无变化和设备事件输入拒绝。
4. 该函数还包含入口保护及 abort/栈保护路径，不能将整个函数说成只有一条 return。额外调用 `0x7446c8` 已确认是 abort 包装。名称解码、完整工厂实现及实际激活条件本轮没有继续还原。

因此该项是**补齐任务清单的静态发现**，不是新发现作弊检测的证据。保存的 IDA disasm 返回 229 条记录；工具记录数不等于 FDE 范围的全部原始指令覆盖，负面结论只限于已恢复正常路径。

原始取证：[ida-audit.json](evidence/ida-audit.json)；结构化映射：[task-map.json](evidence/task-map.json)。
